I added the `m.replace` check so a non-edit event cannot pick its formatted body from a made-up `m.new_content`.
- Task 1-3 follow-ups handled: link scheme allow-list (`http`, `https`, `mailto`, no userinfo, at most 2,048 bytes before and after normalization; anything else becomes text; `matrix.to` and `matrix:` parse to mentions); nesting capped at 32 (deeper content flattened to text); paragraphs, headings, code blocks and rules capped at 1,000 per message, which also covers plain bodies (`from_plain`), plus the 16,384-char, 2,000-inline and 1,000-list-item caps. The `Inline::Link.url` doc now matches reality. Not done (other tasks): ambiguity flag on reply and membership names, `Option` for an unloaded reply sender, reaction-group and reaction-key caps.
- Found by test: dropping a parsed tree of a few thousand nested elements overflows the stack (recursive `Drop` in ruma-html; reproduced at 6,000 `<div>` in a debug test thread, 2 MB stack), and an event can carry about 13,000 open tags. `from_html` therefore counts start-tag candidates (`<` followed by an ASCII letter) before parsing (`too_many_tags`, `MAX_TAGS` = 4,000) and uses the plain body above that. Security follow-up: the first guard mirrored the tokenizer (counting `</` as a close) and was bypassed by `<b></>` (ignored by html5ever), `</ x>` and `<!--</-->` (bogus comments), which parsed 10,900 levels deep. The count does not depend on tokenizer behaviour: a tree cannot be deeper than its element count, and every element needs such a candidate. It over-counts closed, void and commented tags (safe side). Why 4,000: 6,000 nested elements overflowed a 2 MB debug thread (smallest stack and largest frames we run on, tokio workers default to 2 MB), so 4,000 keeps a margin of 1.5x; the test parses exactly 4,000 nested `div`, `b`, `blockquote` and `ul`/`li` in a debug test thread. Normal messages are far below it (the 2,000-inline cap alone needs about 3,000 tags). Tests: `<b></>`, `</ x>`, `<!--</-->`, 5,000 `<div>`, and the max-depth case.
- Security follow-ups (linkifier and links): trailing-`)` stripping was quadratic (each strip rescanned the token; a 65,000-`)` token took 9 s in release, 39.5 s in debug). Parens are now counted once and updated while stripping, and tokens longer than `MAX_URL_BYTES` + 64 (`MAX_TOKEN_MARGIN`) are skipped, since they cannot be links. Regression test `linkify_trailing_parentheses_is_linear` (65,000 `)`, under 1 s). `mailto:` links keep only `subject`, `body`, `cc` and `bcc` (case-insensitive) in the query, so `?attach=/path` is dropped (`keep_safe_mailto_query`; the query is re-encoded, so `@` becomes `%40`).
- Not fixable in the core (spoofing): link and mention labels can differ from their targets (`<a href="https://evil.example">https://bank.example</a>`, a pill labelled with another user's name). Task 10 must show the real URL (or the real user/room ID) before opening a link or acting on a pill, and not rely on the label. Also on the Phase 3 human checkpoint.
- Choices the plan left open: the paragraph cap is 1,000 (`MAX_BLOCKS`); the text cap yields at most 16,385 chars (16,384 plus the ellipsis); a spoiler span flattens block elements inside it; `table` cells are joined by two spaces per row; the linkifier keeps `)` when balanced (Wikipedia-style URLs) and trims leading `( < ' "`.

## Phase 3 / Task 5 notes
- New private module `crates/core/src/outgoing.rs` (`outgoing_content`, Q10). Mention labels are linked at their first free occurrence (ranges never overlap; a label inside another mention's range is skipped), the label is backslash-escaped (all ASCII punctuation) and the user ID percent-encoded (`@alice:localhost` gives `%40alice%3Alocalhost`, accepted by Synapse and our mapper). `body` is the text as typed; `m.mentions` lists only users whose label was found. Text, notice and emote go through `*_markdown`.
- Raw HTML (Task 1 security note): ruma's `parse_markdown` is private and passes `Html`/`InlineHtml` through, so the formatted body is sanitized after the fact with ruma-html's `SanitizerConfig::strict()` plus `remove_elements(["img", "script", "style"])` (those go with their content; other unknown tags are dropped and their text kept). This runs only when the source contains a `<` (raw HTML cannot exist without one) and at most 1,000 of them; above that the message is sent as plain text with no `formatted_body`, so the tree parsed here stays small (Task 4's deep-nesting `Drop` issue). Tests: `<img src=x onerror=alert(1)>`, `<script>`, `<p onclick>`, `<iframe>`, `javascript:` links (unit), and an integration test that reads the event from the server and checks `formatted_body` holds `<strong>b</strong>` and no `<img`, `<script` or `onerror`. Code spans keep their `<` as `&lt;` (tested).
- Deviation found by test: ruma returns no `formatted` for a text whose only markdown is a newline (`a\nb`). The plan wants `<br />`, so `line_breaks_html` builds it (escaped lines joined by `<br />\n`) when there is no formatted body and the text has a newline.
- Engine: `Selected { room_id, timeline: Arc<Timeline>, task, tasks: JoinSet<()> }`; `Selected::stop` aborts the forwarder and `JoinSet::shutdown`s the action tasks before the timeline drops. `Command::Send`, `RetrySend` and `DiscardSend` go through `Engine::run_action`, which answers `NotLoggedIn` / `NoRoomSelected` as `ActionFailed` and otherwise spawns in the JoinSet. Reply: the item is resolved by `unique_id` (`ItemNotFound`), must be an event with `can_be_replied_to` and an event ID (`NotAllowed`), then `Timeline::send_reply`; otherwise `Timeline::send`. Errors from the SDK are the fixed text "the message could not be queued". Retry: `unwedge()` only when the echo is `SendingFailed { is_recoverable: false }`, then `room.send_queue().set_enabled(true)`. Discard: `abort()`, then `set_enabled(true)` even when the abort failed. No local echo gives `NotAllowed`.
- Resume (Q11): `sync::ResumeDetector` and `ResumeSink` (a `StateSink` wrapper that sees every published state, unlike the coalescing watch slot) call back on `Running` after `Offline` or `Reconnecting`. `forward_sync_state` turns that into `client.send_queue().set_enabled(true)` in the same task as the supervisor (a `Notify` plus a select), so no detached task holds the client. `run_supervised` gained an `on_resume` argument.
